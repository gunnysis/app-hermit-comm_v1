# UI/UX 및 접근성(A11y) 코드 리뷰 보고서

본 문서는 '은둔마을' 앱의 UI/UX 일관성 및 접근성 준수 여부를 검토한 결과입니다.

## 1. 개요
- **검토 대상**: `src/shared/components`, `src/features/*/components` 등 주요 UI 컴포넌트
- **주요 기준**: WCAG 2.1 (AA 레벨), Apple/Google 디자인 가이드라인, UX 베스트 프랙티스

---

## 2. 주요 발견 사항

### ✅ 긍정적인 부분 (Best Practices)
1.  **세밀한 접근성 라벨링**: `PostCard`에서 게시글 정보를 요약하여 제공하는 `buildAccessibilityLabel` 등 스크린 리더 사용자를 배려한 구현이 돋보임.
2.  **풍부한 피드백 (UX)**: 버튼 및 카드 클릭 시의 햅틱 피드백(`expo-haptics`)과 스프링 애니메이션(`Animated`)이 적용되어 사용자 경험이 우수함.
3.  **안전한 콘텐츠 렌더링**: `PostBody`에서 HTML 콘텐츠를 렌더링할 때 XSS 방지 및 에러 바운더리를 통한 Fallback 처리가 잘 되어 있음.
4.  **일관된 디자인 시스템**: `DESIGN_TOKENS.md`와 `shared-palette.js`를 통해 테마 색상이 체계적으로 관리되고 있음.
5.  **다크 모드 지원**: 대다수 컴포넌트에서 `isDark` 상태를 체크하여 색상을 적절히 분기하고 있음.

### ⚠️ 개선 권고 사항 (Findings)

#### 1. 색상 대비 (Color Contrast) - **중요**
현재 브랜드 컬러(`happy-500` 등)와 흰색 텍스트의 대비가 매우 낮아 가독성에 문제가 있습니다.
-   **현황**: `happy-400` (#FFCF33), `happy-500` (#FFC300) 배경에 흰색 텍스트 사용 시 대비율이 **1.5:1 ~ 1.8:1** 수준입니다. (WCAG AA 기준은 최소 4.5:1)
-   **권고**: 
    -   배경색을 어둡게 하거나, 텍스트 색상을 어두운 색(예: `happy-900` 또는 `stone-800`)으로 변경해야 합니다.
    -   `Button`, `SortTabs`, `FloatingActionButton` 등 주요 액션 요소의 가독성 확보가 시급합니다.

#### 2. 터치 타겟 크기 (Touch Target Size)
일부 요소의 클릭 영역이 권장 크기(44x44px)보다 작게 설정되어 있습니다.
-   **현황**: `Button`의 `sm`, `md` 사이즈가 각각 약 34px, 40px 높이로 계산되어 정밀한 조작이 어려울 수 있습니다.
-   **권고**: 최소 높이를 44px로 상향하거나, `hitSlop`을 적용하여 터치 영역을 확장해야 합니다.

#### 3. 스크린 리더 흐름 최적화
-   **현황**: `PostCard`처럼 컨테이너 자체에 `accessibilityLabel`이 있는 경우, 내부의 개별 텍스트 요소들이 중복으로 읽힐 수 있습니다.
-   **권고**: 컨테이너가 포커스될 때 내부 요소는 숨기거나(`importantForAccessibility="no-hide-descendants"`), 스크린 리더의 포커스 흐름을 점검해야 합니다.

#### 4. 로딩 및 상태 표시
-   **현황**: 
    -   `Button` 내의 `ActivityIndicator`에 별도의 접근성 라벨이 없어 로딩 중임을 스크린 리더 사용자가 인지하기 어렵습니다.
    -   `Skeleton` 및 `Loading` 컴포넌트가 `accessibilityRole="progressbar"` 또는 적절한 라벨 없이 렌더링되고 있어, 보이지 않는 사용자에게는 '비어있는' 상태로 인식될 수 있습니다.
-   **권고**: 
    -   `ActivityIndicator`에 `accessibilityLabel="로딩 중"` 추가.
    -   스켈레톤 UI가 화면을 채울 때, 개별 스켈레톤 조각을 읽어주기보다 컨테이너 수준에서 "콘텐츠 로딩 중"이라는 하나의 안내를 제공하고 내부 요소는 숨기는 것이 효율적입니다.

#### 5. 웹 접근성 (Multi-platform 고려)
-   **현황**: Expo를 통한 웹 지원 시, 키보드 내비게이션 및 포커스 링 시각화가 부족할 수 있습니다.
-   **권고**: `Pressable` 요소에 키보드 포커스 시 시각적 표시(Outline)가 나타나도록 처리하고, `onKeyDown` 등을 통해 엔터/스페이스 바 동작이 보장되는지 확인해야 합니다.

## 3. 컴포넌트별 상세 분석

| 컴포넌트 | 항목 | 상태 | 내용 |
| :--- | :--- | :---: | :--- |
| **Button** | 색상 대비 | ✅ | Primary 텍스트를 어두운 색으로 변경하여 대비 확보 |
| | 터치 영역 | ✅ | `minHeight: 44` 적용 완료 |
| **Input** | 접근성 | ✅ | 라벨 및 에러 메시지 연동, 포커스 상태 시각화 우수 |
| **PostCard** | 접근성 | ✅ | 자식 요소 포커스 제외(`importantForAccessibility`) 적용 |
| **SortTabs** | 상태 표시 | ✅ | `accessibilityState={{ selected: ... }}` 적용 우수 |
| | 색상 대비 | ✅ | 활성 탭 텍스트 색상 보정 완료 |
| **PostBody** | 보안/UX | ✅ | HTML 필터링 및 에러 처리 우수 |
| | 접근성 | ⚠️ | 이미지 요소의 `alt` 텍스트 보강 필요 |
| **Skeleton** | 접근성 | ✅ | 컨테이너 레벨 로딩 안내 및 자식 요소 숨김 적용 |
